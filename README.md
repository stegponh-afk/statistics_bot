# statistics_bot — помощник админов каналов, групп и ботов

Telegram-бот на Bot API 10.3: ответы в группах приходят **ephemeral-сообщениями**
(их видит только тот, кто вызвал команду), а меню оформлено в «новом стиле» —
кнопки встроены прямо в сообщение (Rich Messages).

## Что умеет

- 📊 **Статистика групп** — сообщений за сегодня / 7 / 30 дней, активные
  участники, топ-5, популярные слова, активность по часам, приток/отток участников.
- 📣 **Статистика каналов** — подписчики сейчас, подписки/отписки за сегодня и вчера,
  рост за 7 и 30 дней, постов в день, реакции на пост (среднее и лучший пост), таблица по
  дням, топ постов по реакциям. Просмотры Telegram ботам не отдаёт. `/stats` для админов,
  `/me` для любого участника — ответ видит только он. Те же экраны есть в личке
  («Мои чаты → чат → Статистика»). Хранятся только метаданные и частоты слов,
  текст сообщений в базу не пишется.
- 🔒 **Обязательная подписка в группе** — сообщения неподписанных удаляются, а им
  приходит ephemeral-подсказка с кнопками «Подписаться» и «Проверить».
  Администраторы, анонимные админы и белый список не проверяются.
- 🚪 **Заявки на вступление** — в группе или канале со вступлением «по заявке» бот
  одобряет только тех, кто подписан на ваши каналы. Спам не попадает внутрь вообще,
  и это единственный вариант гейта, который работает для каналов.
- 👋 **Приветствие новичков и капча** — зашедший в группу получает сообщение, которое
  по умолчанию видит **только он сам**, так что чат не засоряется. Капча включает
  новичку немоту, пока он не нажмёт «Я не бот».
- 📬 **Отчёты админам** — бот сам присылает в личку сводку по чату каждый день (за
  вчера) или раз в неделю (по понедельникам за 7 дней).
- 🔑 **HTTP API для ваших ботов** — один запрос `GET /v1/check?user_id=…` с
  API-ключом отвечает, подписан ли пользователь на ваши каналы, и отдаёт ссылки
  на недостающие.

## Быстрый старт

```bash
cp .env.example .env      # заполнить BOT_TOKEN, OWNER_IDS, POSTGRES_PASSWORD, API_PUBLIC_URL
docker compose up -d --build
docker compose logs -f bot
```

Compose поднимает бота, PostgreSQL 16 и Redis 7; миграции применяются при старте
(`alembic upgrade head`). Порт `API_PORT` (по умолчанию 8080) пробрасывается наружу —
поставьте перед ним реверс-прокси с HTTPS.

## Настройка в BotFather

1. `/setprivacy` → **Disable** — иначе бот не видит обычные сообщения в группах, где он
   не администратор. После смены режима бота нужно **удалить и заново добавить** в
   группы.
2. `/setjoingroups` → **Enable**.
3. Команды выставляются самим ботом при старте (`/setcommands` не нужен): в группах
   `/me`, `/help`, для админов `/stats`, `/whitelist`; в личке `/start`, `/chats`,
   `/keys`, `/help`.

## Подключение чатов

**Группа.** Добавьте бота и назначьте администратором с правом «Удалять сообщения»
(для гейта) и «Приглашать пользователей» (чтобы бот мог получить ссылку на приватный
канал). Чат появится в «Мои чаты» у всех его администраторов.

**Канал.** Добавьте бота администратором (права можно не выдавать) — без этого Telegram не
позволяет вызывать `getChatMember`, то есть проверять подписку.

**Гейт.** В личке: «Мои чаты» → группа → «Каналы» → отметить каналы →
«Обязательная подписка: ВКЛ». Белый список — там же, либо командой `/whitelist`
ответом на сообщение участника.

**Комментарии к каналу.** В самом канале пишут только админы, поэтому подписка
проверяется в его группе обсуждений. На карточке канала есть переключатель «Подписка в
комментариях»: бот находит группу обсуждений (`getChat.linked_chat_id`), привязывает к ней
канал и включает там гейт. Бот должен быть добавлен в группу обсуждений администратором
с правом «Удалять сообщения».

## HTTP API

Ключ создаётся в личке («API-ключи» / `/keys`), показывается один раз и привязывается к
каналам. В своём боте перед выдачей контента:

```bash
curl -H "Authorization: Bearer sb_XXXX" \
  "https://api.example.com/v1/check?user_id=123456789"
```

```json
{
  "ok": true,
  "user_id": 123456789,
  "subscribed": false,
  "missing": [
    {"chat_id": -1001234567890, "title": "Мой канал", "username": "mychannel",
     "invite_link": "https://t.me/mychannel"}
  ],
  "unavailable": [],
  "cached": false,
  "checked_at": "2026-09-08T10:00:00Z"
}
```

- `subscribed=false` → покажите пользователю кнопки со ссылками из `missing` и
  повторите запрос после подписки. Результат кэшируется `FORCESUB_CACHE_TTL_SECONDS`
  (60 с); `&force=1` проверяет заново.
- `unavailable` — каналы, которые не удалось проверить (бот больше не админ канала,
  `bot_not_admin`, или лимит Telegram, `rate_limited`). Они не считаются против
  пользователя. Если проверить нельзя ни один канал — `503 telegram_unavailable`.
- `GET /v1/channels` — каналы ключа (для отрисовки кнопок заранее).
- Ошибки: `400 bad_request`, `401 unauthorized`, `429 rate_limited` (+ `Retry-After`).
  Лимит `API_RATE_LIMIT_PER_MINUTE` на ключ (600), для неавторизованных запросов —
  `API_UNAUTH_RATE_LIMIT_PER_MINUTE` на IP.

Пример на aiogram:

```python
async def ensure_subscribed(bot, user_id) -> bool:
    async with aiohttp.ClientSession() as http:
        async with http.get(
            f"{API}/v1/check", params={"user_id": user_id},
            headers={"Authorization": f"Bearer {KEY}"},
        ) as resp:
            data = await resp.json()
    if data.get("subscribed"):
        return True
    kb = InlineKeyboardBuilder()
    for ch in data.get("missing", []):
        if ch["invite_link"]:
            kb.row(InlineKeyboardButton(text=ch["title"], url=ch["invite_link"]))
    kb.row(InlineKeyboardButton(text="✅ Проверить", callback_data="recheck"))
    await bot.send_message(user_id, "Подпишитесь на каналы:", reply_markup=kb.as_markup())
    return False
```

## Проверка подписки без кода

- **Ключ в ссылке.** Конструкторы ботов обычно умеют «HTTP-запрос», но не заголовки:
  `GET /v1/check/<ключ>?user_id=<id>` и `GET /v1/channels/<ключ>` работают без
  `Authorization`. Готовая ссылка показывается при создании ключа.
- **Награда за подписку.** На карточке канала («Чаты» → канал → «Награда за подписку»)
  админ сохраняет сообщение для подписчиков и получает ссылку `t.me/<бот>?start=sub_…`,
  а кнопкой «Опубликовать кнопку в канал» — сразу пост с кнопкой «Получить». Пользователь
  переходит, бот проверяет подписку через `getChatMember` и либо отдаёт материал, либо
  просит подписаться и нажать «Проверить». Чужой бот и код не нужны.

## Боты и рассылки

Раздел «Боты» в личке: у каждого вашего бота есть API-ключ для проверки подписки
(см. выше). «Рассылка» → «Новая рассылка»: отметить каналы и группы, где есть этот бот,
прислать сообщение (текст с форматированием или медиа с подписью), при желании добавить
кнопки-ссылки (`Текст | https://…` по одной на строку) и выбрать: **прямо сейчас**,
**к определённому времени** (`ДД.ММ.ГГГГ ЧЧ:ММ` или `ЧЧ:ММ`) или **циклично** (дни недели +
время). Время в `DEFAULT_TIMEZONE`. Планировщик проверяет очередь каждые 30 секунд;
в «Мои рассылки» видны статус, счётчики доставки, пауза, «Отправить сейчас» и удаление.

## Заявки на вступление

Гейт наоборот: сообщения не удаляются, потому что внутрь никто не попадает.

1. В самом чате включите вступление по заявке: **группа** — Управление → Тип группы →
   Кто может вступать → «По заявке»; **канал** — то же в настройках канала (для
   приватного канала это «Заявки на вступление» у пригласительной ссылки).
   Без этого Telegram не создаёт заявок вообще, и переключатель в боте ничего не даёт;
   бот читает эту настройку через `getChat().join_by_request` и пишет на карточке чата,
   что она не включена.
2. Боту нужно право **«Добавлять участников»** — им одобряются заявки.
3. «Мои чаты» → чат → «Каналы» → отметьте нужные каналы → «Заявки: ВКЛ».

Дальше бот берёт каждый `chat_join_request` на себя. Подписан — одобряет сразу.
Не подписан — заявка остаётся висеть, а человеку приходит в личку список каналов с
кнопками и «Проверить».

Написать незнакомому человеку бот может благодаря `ChatJoinRequest.user_chat_id`:
Telegram открывает приватный чат, в который разрешено писать **пять минут**, даже если
тот никогда не запускал бота. Нажимать «Проверить» при этом не обязательно: как только
человек подпишется, придёт `chat_member` от канала, и заявка одобрится сама — это же
снимает проблему истёкшего пятиминутного окна.

Заявку, которую администратор рассмотрел вручную, Telegram никак не анонсирует, поэтому
строка в `join_requests` удаляется при первой неудачной попытке одобрения, а всё
оставшееся старше 30 дней подчищает ежедневный job.

## Приветствие новичков и капча

«Мои чаты» → группа → **«Приветствие»**. Пришлите сообщение, которое получит новичок:
текст (можно markdown), фото, видео или файл с подписью. Подстановки `{name}` (имя
новичка) и `{title}` (название чата) работают в тексте без форматирования Telegram —
если разметка задана entity-ами, их смещения сдвинулись бы, поэтому подстановка
пропускается.

Переключатель «Видит» выбирает, приходит приветствие **только новичку**
(ephemeral, по умолчанию) или всем в чате. Если Telegram откажется доставить
ephemeral-сообщение, бот отправит обычное — приветствие не теряется.

**Капча** требует у бота право «Блокировать участников». Новичку выдаётся немота
(`restrictChatMember`) и ephemeral-вопрос с кнопкой «Я не бот»; после нажатия права
восстанавливаются из `getChat().permissions`, то есть ровно до умолчаний чата, и следом
приходит приветствие. Ожидание нажатия живёт в Redis сутки, поэтому чужая или
устаревшая кнопка ничего не делает. Если вызов не удалось доставить ни ephemeral, ни
обычным сообщением, немота снимается сразу — человек не может остаться заблокированным
из-за проверки, которую он не видел.

Бот получает `chat_member` только будучи администратором группы — без этого он не
узнает о новичках.

## Отчёты админам

«Мои чаты» → чат → **«Отчёты»**: включить, выбрать «каждый день» или «раз в неделю»,
задать время (`ЧЧ:ММ` в часовом поясе чата) и при желании посмотреть пример кнопкой
«Показать пример». Отчёт уходит в личку всем администраторам чата, которые запускали
этого бота.

Период всегда закрытый: дневной отчёт — за вчера, недельный — за прошедшие 7 дней,
поэтому цифры в нём уже не изменятся. Для группы это сообщения и сравнение с
предыдущим периодом, сколько человек писали, приток/отток участников, топ-3 активных и
популярные слова; для канала — подписчики, посты, среднее число реакций и лучший пост.
Планировщик проверяет очередь раз в 5 минут; `chats.digest_last_day` не даёт отправить
один и тот же отчёт дважды.

## Карточка чата: «Что включено»

Переключатель показывает флаг, а не результат: «Обязательная подписка: ВКЛ» ничего не
говорит о том, что бот не админ в требуемом канале и гейт по факту мёртв. Поэтому в
карточке есть блок, где каждая включённая функция помечена «работает» либо «не работает»
с точной причиной и инструкцией — не отмечен канал, нет права «Удалять сообщения» /
«Добавлять участников» / «Блокировать участников», не включены заявки в самом чате.

Часть этих условий бот не может узнать из апдейтов (их меняют в настройках Telegram, и
никакого события при этом не приходит), поэтому кнопка «Обновить» перечитывает права
через `getChatMember` и настройки чата через `getChat`.

## Комментарии под постами рассылки

Комментарии — свойство канала, а не поста: они появляются, когда к каналу привязана
группа обсуждений, и в `sendMessage`/`sendPhoto` нет ни одного поля, чтобы включить или
выключить их для конкретной публикации. Поэтому переключателя нет — вместо него экран
предпросмотра рассылки перед отправкой сообщает по каждому выбранному каналу, будут
комментарии или нет, и как привязать группу обсуждений.

## Что хранится

`message_events` — chat_id, user_id, дата, тип, длина текста (без самого текста);
`word_stats_daily` — частоты слов по дням. Старше `STATS_RETENTION_DAYS` (90) удаляется
ежедневно. Часовой пояс для «сегодня» и активности по часам — `DEFAULT_TIMEZONE`.

## Как это устроено (ephemeral и «новый стиль»)

- Команды в группах помечены `is_ephemeral=True` в `setMyCommands`: выбранная из меню
  команда невидима для остальных, ответ идёт через `ephemeral_message_parameters`.
- Кнопки внутри ephemeral-сообщения обрабатываются через `editEphemeralMessageText`;
  кнопки на публичном сообщении — новым ephemeral с `replace_callback_query_message`
  (`app/ui/screen.py::respond`).
- Меню рендерится как `InputRichMessage` с `InputRichBlockButtons`; в «Настройках»
  можно вернуть классическую клавиатуру. При отказе Telegram от rich-формы всегда есть
  текстовый fallback.

## Разработка

```bash
python -m venv .venv && .venv/Scripts/pip install -r requirements-dev.txt
.venv/Scripts/ruff check . && .venv/Scripts/pytest -q
```

Тесты идут на sqlite в памяти с `MemoryCache` и `FakeBot` (`tests/fakes.py`), Redis и
PostgreSQL не нужны.

Структура: `app/handlers` (private / group / channel), `app/middlewares` (сессия БД,
контекст чата, гейт, лог статистики), `app/services` (чаты и админы, статистика,
токенизатор, проверка подписки, ключи, rate limit), `app/screens` (сборка экранов),
`app/ui` (рендер rich/ephemeral), `app/api` (aiohttp), `alembic/`.
